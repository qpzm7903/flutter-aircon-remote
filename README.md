# 空调遥控

Android 手机内置红外遥控器。**v0.3.1 已实现**，见 [0.3.1 版本说明](docs/versions/0.3.1.md)。

## ⚠️ 从 v0.3.0 及更早版本升级

v0.1–v0.3.0 的 CI APK 使用每次运行临时生成的 debug 签名，无法直接覆盖安装 v0.3.1（会提示签名不一致）。**请先记下空调名称和遥控协议型号（变体），再卸载旧版并安装 v0.3.1。卸载会删除所有已保存的空调和设置，需要重新添加。** 这次只需卸载一次，此后使用同一正式签名、版本号递增的发布版本可直接覆盖安装。

## v0.3.1 已实现功能

- 水平扫风：关 / 自动 / 最左 / 偏左 / 居中 / 偏右 / 最右。
- 局部垂直扫风：上部 / 中部 / 下部。
- 华氏度：61–86 °F。
- 定时（实验）：30 分钟–24 小时，显示剩余时间估算。
- 空调 Wi‑Fi 一次性按键。
- 温度显示按协议顺序切换的“下一档”按钮。

水平扫风、局部垂直扫风、华氏度、定时和 Wi‑Fi 键默认隐藏，可在设备设置中开启；YX1FSF 新建设备默认显示华氏切换。温度显示沿用原有可见性，改用“下一档”操作。I‑Feel 不支持（上游没有测温报文，手机也没有可信室温）。应用内 v0.2 → v0.3 数据迁移可保留设备和状态；历史 CI APK 的签名迁移仍须按上方提示卸载，无法保留本地数据。

## 功能

- 电源、自动 / 制冷 / 除湿 / 送风 / 制热，16–30 °C 温度调节，长按每 150 ms 连续调温。
- 自动与三级风速、垂直扫风及固定位置、强劲、灯光、换气/防霉、睡眠与温度显示。
- 每次有效状态变化发送完整红外帧；快速操作合并为最新状态，发送不重叠。
- 最多保存 20 台空调，可命名、设置房间和图标、拖拽排序；每台设备独立保存状态；启动恢复状态但不发送。支持系统 / 浅色 / 深色主题。
- 无红外发射器时提示并禁用遥控操作，添加设备、设置和诊断仍可使用。
- 诊断页查看与复制日志，日志按日保存并保留七天。

## 支持的品牌与协议

目前支持 **格力 Gree YAW1F、YBOFB、YX1FSF**，38 kHz、8 字节有状态协议。YBOFB 的 ModelA 位不同，YX1FSF 另支持“节能 Econo”模式。不是所有格力空调均兼容，请按实际机型试用。健康/负离子位缺乏验证，当前不提供；0.3.1 支持水平扫风、局部垂直扫风、华氏度、实验定时、Wi‑Fi 一次性按键与温度显示逐档切换，不支持 I‑Feel、红外学习或外接发射器。

需要 Android 15（API 35）或更高的 arm64 手机及内置红外发射器。目标 API 37。应用仅请求普通权限 `TRANSMIT_IR`，不需运行时授权；无红外手机也可安装。红外没有反馈，界面显示假定状态，请将手机发射器对准空调。自动模式锁温 25 °C，除湿锁低风，送风禁用调温；切换模式时不兼容的功能会关闭，切回不会恢复。

## 添加空调与配对测试

红外是单向的：手机只能发信号，无法自动发现或检测空调，也无法读取真实状态。首页的记录由你添加和命名，遥控协议型号不是发现的空调。

点击“添加空调”，填写名称、房间和图标，确认格力品牌，再把手机顶部红外口对准空调接收窗，保持几米以内、无遮挡。配对依次发送 YAW1F、YBOFB、YX1FSF 的开机测试帧（前两种为制冷 26 °C，YX1FSF 为节能 26 °C）。听到滴声或看到面板响应后点“有响应”；否则试下一个，也可重发。三种都无响应时查看排查提示，仍可保存或重新测试；没有红外的手机可跳过，记录会标为未做配对测试。取消不会保存任何记录。

采用第一个有响应的型号，不能唯一识别遥控器：YAW1F 与 YX1FSF 的非节能帧完全相同。如果实体遥控器有“节能”键，请在设备设置的“遥控协议型号”中选择 YX1FSF。部分按键不符时可手动换型或重新配对；重新配对结果先进入设置草稿，保存后生效。

## 按钮如何确定

按钮来自协议声明的能力，再减去该设备设置中隐藏的功能；当前模式约束决定按钮是否可点。设置中可调整模式、风速、扫风、附加功能和温度范围，不能添加协议不支持的能力。“按钮说明”列出可用、已隐藏、此协议不支持、当前模式不可用及原因。隐藏功能发码时保持默认：灯光为亮，其余为关；更改设置仅归一化状态，不发码。

## v0.1 数据迁移（应用内逻辑）

以下逻辑仅适用于签名兼容的覆盖安装；历史 CI APK 升至 v0.3.1 需卸载，数据会被删除。升级首次启动会把 v0.1 的所选协议和对应状态迁为一台“我的空调”（未做配对测试），主题保留，启动不发码。迁移先写状态再写设备索引，最后提交版本；重试时若设备索引已存在，仅提交版本，不覆盖已有设备或状态；其他协议的旧状态不迁入，旧键保留以便排查或降级。全新安装显示空列表。

## 下载 APK

在本仓库 **Actions → Build and Release → 成功的运行 → Artifacts** 下载 `*-android-aarch64.apk` 压缩包并解压安装（需要登录 GitHub，产物保留 7 天）。也可打开仓库 **Releases**，从 `v*` 版本附件下载 APK；预发布版本会标记 prerelease。首次安装需要允许浏览器或文件管理器安装未知来源应用。

## 构建方式

环境：Flutter 3.47.7 / Dart 3.13.5、JDK 21、Android SDK 37、NDK 30.0.16248370。项目采用 Groovy、AGP 9.2.1、Kotlin 2.3.21、Gradle 9.5.1。

```bash
export PATH=/home/box/sdk/flutter/bin:$PATH
export ANDROID_HOME=/home/box/sdk/android
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64
```

输出：`build/app/outputs/flutter-apk/app-release.apk`。可用 `flutter run --dart-define=FAKE_IR=true` 在无红外设备上演示（模拟发送，不会控制空调）。可选 `USE_ALIYUN_MAVEN=true` 启用参考项目的 Maven 镜像。

## 签名

从 v0.3.1 起，正式发布使用稳定的 release keystore，由 CI secrets `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 提供。tag 构建缺失签名 secrets 时失败，任何不完整配置也会失败；同仓库 push 缺失时醒目警告并回退 debug 签名，fork PR 则提示后使用 debug 签名。这些 debug 签名产物不用于正式升级。

CI 的 “Verify APK signer” 步骤打印签名证书，并在 release 签名模式下检测到 debug 签名时失败。可自行检查下载的 APK：

```bash
apksigner verify --print-certs app-release.apk
```

将输出的证书 SHA-256 与本 README / 发布说明公布的值核对：

签名证书 SHA-256：F5:18:0A:84:CC:33:14:5D:6E:05:19:BE:63:7B:D5:50:79:26:BB:19:DA:2F:A8:2D:5E:EA:DD:3E:73:80:F3:A6

versionCode 使用 `major*10000+minor*100+patch`，v0.3.1 为 `301`（历史版本均为 `1`）；pubspec 为 `0.3.1+301`。本地未配置签名时仍回退 debug 签名。密钥与凭据由所有者离线备份，永不提交；丢失会导致用户再次被迫卸载。
