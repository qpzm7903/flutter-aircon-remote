# v0.3.1：发布签名与版本号修复

本次为补丁发布，不变更应用功能。

## 问题

v0.1–v0.3.0 的 CI APK 使用各 GitHub runner 临时生成的 debug keystore 签名，每次构建的证书可能不同，覆盖安装会提示“签名不一致”（signature differs）。这些版本的 versionCode 也始终为 1，未能随发布递增。

## 修复

- 正式发布改用稳定的 release keystore，通过 CI secrets `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 注入。
- tag 构建缺少签名 secrets 时直接失败；任何部分配置均失败。同仓库 push 缺少配置时醒目警告并回退 debug 签名；fork PR 则提示后回退 debug 签名。
- CI “Verify APK signer” 步骤打印签名证书；release 签名模式若产出 debug 签名 APK 则失败。
- versionCode 使用 `major*10000+minor*100+patch`；v0.3.1 的 pubspec 为 `0.3.1+301`，versionName 为 `0.3.1`，versionCode 为 `301`，大于旧值 1。CI 元数据去掉 `+build` 后缀。

## 用户影响：一次卸载

**从 v0.1–v0.3.0 的历史 CI APK 升至 v0.3.1，必须先卸载旧版。卸载会删除所有保存的空调和设置。** 建议先记下每台空调的名称、遥控协议型号（变体）及需要恢复的设置，再卸载、安装新版并重新添加。

完成这一次迁移后，未来使用同一正式签名且 versionCode 递增的版本可覆盖安装，保留数据。

## 验证签名

使用 Android SDK Build Tools 提供的命令检查下载的 APK：

```bash
apksigner verify --print-certs app-release.apk
```

核对输出的签名证书 SHA-256；正式证书的 SHA-256 将公布在发布说明和 README 中。debug 签名的测试产物不用于正式升级。

## 维护者注意

keystore 及其凭据由所有者离线备份，永不提交至仓库（包括 `key.properties`）。后续发布必须使用同一密钥；丢失密钥意味着无法签出兼容更新，用户将再次被迫卸载并丢失本地数据。

## CI 额外校验（评审后补充）

- tag 构建会校验 APK 签名证书 SHA-256 必须等于 `build.yml` 中固定的 `EXPECTED_CERT_SHA256`（`F5:18:0A:84:CC:33:14:5D:6E:05:19:BE:63:7B:D5:50:79:26:BB:19:DA:2F:A8:2D:5E:EA:DD:3E:73:80:F3:A6`），防止 secrets 被误换成其他密钥。
- tag 构建会校验 tag 版本号与 `pubspec.yaml` 版本号一致，不一致直接失败。
