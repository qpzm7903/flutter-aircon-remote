# v0.3.0 — 水平扫风、Gree 协议缺口补全（华氏度 / 局部扫风 / 定时 / Wi‑Fi 键）

设计依据：[架构设计 §20–§26](../architecture.md)（§1.2、§3、§4、§5.3、§12、§14–§16 中带「v0.3.0 修订」标记处以新章节为准）。
协议依据：IRremoteESP8266 master 的 `ir_Gree.h`、`ir_Gree.cpp`、`ir_Gree_test.cpp`、`IRsend.h`（`/workspace/refs/irremote/`）。
本文给出范围、协议审计表、用户故事、验收标准、迁移说明与测试清单。**本版已实现**；实现记录见 `plan.md` 的 M14–M19。仍然只做 Gree，不新增品牌。

## 1. 背景

v0.2 把 `GreeProtocol` 联合体里的一批字段硬写为 0（水平扫风、华氏度、定时、Wi‑Fi、I‑Feel），architecture §1.2 / §5.3 也明确写了“水平扫风不做”。
用户希望：①加上水平扫风（许多壁挂机没有，所以必须能按设备隐藏）；②对照上游把整个 Gree 协议逐字段审计一遍，凡是“手机遥控器合理”的都补上。

## 2. 范围

**包含**
1. 水平扫风 `SwingH`（byte4 bit4–6）：关 / 自动 / 最左 / 偏左 / 居中 / 偏右 / 最右（上游共 7 个值，没有更多）。
2. 垂直局部扫风：`kGreeSwingDownAuto(7)` / `MiddleAuto(9)` / `UpAuto(11)`（byte0 bit6=1 + byte4 低半字节）。
3. 华氏度：`UseFahrenheit` + `TempExtraDegreeF`，61–86 °F。
4. 定时（`TimerEnabled/TimerHalfHr/TimerTensHr/TimerHours`）：30 分钟步长，30 分钟–24 小时，实验功能。
5. 空调 Wi‑Fi 键（`WiFi` 位）：一次性按键，不进入持久状态。
6. 温度显示源（`DisplayTemp`）按上游要求的循环顺序操作（`setDisplayTempSource` 注释），遥控页由下拉改为“下一档”按钮。
7. 全部新能力走既有的数据驱动模型：协议声明 ∩ 设备隐藏覆盖；隐藏/受模式限制时按“中性值”归一化。
8. 持久化 schema v3：旧设备与旧状态原样保留；新增覆盖键 `hiddenHSwings`；为旧设备写入“默认隐藏”种子（幂等）。
9. 版本 0.3.0（pubspec / `AppConstants.version` / `android/app/build.gradle` / README / 文档 / `version_test` / `home_page_test`）。

**不包含**：I‑Feel（§3 审计）、Econo 位、health、红外学习、新品牌、定时的“预约开机/关机”双通道 UI（见 §3 Timer 行）、跨设备批量操作、Gree 云/Wi‑Fi 控制。

## 4. 默认可见性决策

CapabilityOverrides 只做减法，所以“默认”是**创建设备/迁移时写入的种子**（`AcProtocol.recommendedOverrides`），之后完全由覆盖决定，不存在运行时特例。

| 能力 | 新设备（向导） | 迁移的 v0.2 设备 | 理由 |
|---|---|---|---|
| 水平扫风 `swingH` | **隐藏** | **隐藏** | 绝大多数格力壁挂机水平导风板是手动的，多出一排永远无效的按钮比缺失更误导；发出的 SwingH 位对无电动水平摆叶的机型无害，但无法反馈是否有效。用户在设置里一键打开。隐藏时帧中 SwingH=0，与 v0.2 字节完全一致（零回归） |
| 局部垂直扫风 `autoUp/autoMiddle/autoDown` | 隐藏 | 隐藏 | 型号相关；保持 v0.2 的扫风行不变长 |
| 华氏度 `fahrenheit` | 隐藏；**YX1FSF 例外：显示** | 隐藏 | 中国市场默认摄氏；YX1FSF（Soleus 美版窗机，真机帧即华氏）才有明确需求。迁移设备不改变既有界面 |
| 定时 `timer` | 隐藏 | 隐藏 | 实验功能，无实机向量（§3） |
| Wi‑Fi 键 `wifi` | 隐藏 | 隐藏 | 仅带 Wi‑Fi 模块的机型有意义，语义未验证 |
| 温度显示“下一档” | 沿用 `tempDisplay` 特性当前可见性 | 不变 | 仅控件形态变化 |

## 6. 华氏度映射（`UseFahrenheit` + `Temp` + `TempExtraDegreeF`）

空调以“整摄氏度 + 额外 1 °F 标志”表示华氏：`显示 °F = max(61, trunc(1.8·C + 32) + extra)`（`getTemp`）。
上游 `setTemp(F)` 用浮点 `c=(F+0.6−32)/1.8`、`C=floor(c)`、`extra=floor(2c)&1`，其整数边界（F=62、71、80 恰为整数摄氏）依赖浮点舍入，且 F=70、79 不能往返。
**v0.3 不复刻浮点**，用固定的 26 行表（`gree_constants.dart` 的 `greeFahrenheitTable`），规则 = 上游整数算术结果；上游不能往返的两行（70、79）改为 `extra=1` 使显示等于所选值：

| °F | C | extra | | °F | C | extra | | °F | C | extra |
|---|---|---|---|---|---|---|---|---|---|---|
| 61 | 16 | 0 | | 70 | 21 | 1 † | | 79 | 26 | 1 † |
| 62 | 17 | 0 | | 71 | 22 | 0 | | 80 | 27 | 0 |
| 63 | 17 | 1 | | 72 | 22 | 1 | | 81 | 27 | 1 |
| 64 | 18 | 0 | | 73 | 23 | 0 | | 82 | 28 | 0 |
| 65 | 18 | 1 | | 74 | 23 | 1 | | 83 | 28 | 1 |
| 66 | 19 | 0 | | 75 | 24 | 0 | | 84 | 29 | 0 |
| 67 | 19 | 1 | | 76 | 24 | 1 | | 85 | 29 | 1 |
| 68 | 20 | 0 | | 77 | 25 | 0 | | 86 | 30 | 0 |
| 69 | 20 | 1 | | 78 | 25 | 1 | | | | |

† 与上游浮点 `setTemp` 不同的两行（派生）。`Temp` 半字节 = C − 16。硬证据：63 °F → (17,1)（`ir_Gree_test.cpp` `Temperature` 的 `09 01 20 5C …`）、77 °F → (25,0)（`Issue1821`）、61/86 为夹取端点。
所有 26 行满足“按 `getTemp` 公式往返回到原 °F”（测试断言）。摄氏→华氏：取表中 C 相同的**最小** °F（C=26 → 79，每个 16–30 的 C 都有解）；华氏→摄氏：表内 C。
温度范围覆盖（`minTempC/maxTempC`）对华氏的作用：可选 °F = 表中 C 落在 `[effMin, effMax]` 的 °F。自动模式固定 77 °F（C=25）。

## 7. 定时语义

- 状态：`timerMinutes`（0 或 30..1440，30 的倍数）+ `timerSetAtMs`（设定时刻，毫秒，UTC；`timerMinutes>0 ⇔ timerSetAtMs!=null`）。编码用 `setTimer` 同一算法：`enabled = m>=30`、`hours = m~/60`、`half = (m%60)>=30`、`tens = hours~/10`、`units = hours%10`；`m>1440` 夹到 1440。
- 手机不能得知空调是否已到点，所以每次**发帧前**由控制器把剩余时间折算进帧：`remaining = timerMinutes − (now − setAt)/60000`；`<=0` → 定时清除（0, null）；否则向上取整到 30 分钟，并把 `setAt` 重置为 now。因此：①随后的任何按键帧都携带“剩余定时”，不会意外取消定时；②向上取整最多多 29 分钟，界面文案如实说明；③取消定时 = 发送 `timerMinutes=0` 的帧。
- 空调把该字段解释为“关机定时还是开机定时”取决于自身电源状态，上游没有帧向量证实，故特性标“实验”，说明文字写明“以空调实际反应为准”。

## 8. 验收标准

### 8.1 水平扫风
- AC-1 `HorizontalSwing { off, auto, maxLeft, left, middle, right, maxRight }`，原生值 0–6；Byte4 bit4–6 = 该值；`off` 与 v0.2 的 0 相同。
- AC-2 协议声明 `horizontalSwings` 为全部 7 项、特性 `swingH` 在所有模式可用；YAW1F/YBOFB/YX1FSF 一致。
- AC-3 新建设备与迁移设备默认 `hiddenFeatures ∋ swingH`；遥控页不显示水平扫风行；此时任何状态下发送帧 Byte4 高半字节为 0（与 v0.2 逐字节相同）。
- AC-4 在设置里打开后遥控页出现“水平扫风”行（`ChoiceChip`），选择后发送完整帧，向量见 §10。
- AC-5 设置页可单独隐藏某个水平位置（`hiddenHSwings`）；隐藏当前位置时回落 `off`；`off` 不可隐藏。
- AC-6 `swingH` 被隐藏后状态归一化为 `off`，重新显示不恢复。

### 8.2 其他新增
- AC-7 垂直局部扫风三项：Byte0 bit6=1、Byte4 低半字节 = 7/9/11；设置页的单项开关可隐藏（默认隐藏）；解码 8/10/12–15 → `off`。
- AC-8 华氏度：`fahrenheit` 特性打开后温度旁出现 ℃/℉ 切换；切换时发送一帧（空调面板单位随帧改变），目标温度按 §6 表换算且不跳变；℉ 下 −/＋ 步进 1 °F，范围 61–86（受覆盖约束）；Byte3 bit2/bit3 与 Byte1 低半字节符合 §6 表；自动模式固定 77 °F；隐藏 `fahrenheit` 后强制摄氏。
- AC-9 定时：特性打开后遥控页出现“定时”入口，可选 关 / 0.5 h…24 h（步长 0.5 h），显示剩余时间；帧编码与 §7；到点后下次进入/按键自动清除，不发码；隐藏后强制 0。
- AC-10 Wi‑Fi 键：特性打开后出现一次性按钮；点击发送一帧 `WiFi=1`（Byte5 bit6），之后状态中无记忆，下一帧 `WiFi=0`；不写入持久化 JSON。
- AC-11 温度显示：遥控页为“下一档”按钮（循环 off→setpoint→indoor→outdoor→off，受 `tempDisplays` 限制），每次点击发一帧；不再有任意跳转下拉。
- AC-12 隐藏/受模式限制的新特性归一化为中性值：`swingH=off`、`wifiPulse=false`、`timer=0`、`fahrenheit=摄氏`；其他既有中性值规则不变。
- AC-13 “按钮说明”列出：水平扫风各位置、三个局部垂直扫风、四个新特性，状态与实际一致；并有 I‑Feel 不支持的一句话说明。
